# ミニアプリ「一般質問 みんなの論点」設計

日付: 2026-09-30

## 目的

南相馬市議会の一般質問を、議員別・分野別に一覧できるページをつくる。「誰が、どの分野を、どれくらい取り上げてきたか」「市の答弁はどんな方向だったか」を数字と要約で見られるようにし、原文（市議会だより）へたどれる入口にする。

対象読者は市民。試作版として公開し、中身は後から JSON を直して更新できるようにする。

## 方針

- 既存のミニアプリ（`src/pages/apps/odaka.astro` など）と同じ型で作る。Base レイアウト、パンくず、目次、prose 記事。
- 事実データはすべて JSON に置き、ページ側は表示と絞り込みだけを担う。サイトは静的なまま。
- データは市議会だよりの PDF を読んで書き起こす（案A）。AI（Claude）が抽出・分野分類・要約・方向性の判定・トピック分析を行い、その結果を JSON に書く。ページ表示時に AI は動かさない。
- 収録範囲は現任期の定例会すべて。現任期は2022年11月20日投票の市議選から始まるため、令和4年12月定例会（Vol.68 令和5年2月1日号と見込む）から令和8年6月定例会（Vol.82 令和8年8月1日号）までの15回を対象とする。号と定例会の対応は各号で確かめる。
- 答弁の方向性は、議会だよりに載った答弁の要約だけをもとに判定する。会議録全文は判定に使わず、リンクだけ置く。
- 中立性: 他の議員を扱うため、議員の順位付けやスコアは出さない。件数と分野の分布だけを示す。方向性は市側の答弁の性質として示し、議員の評価と結びつけない。
- 断定を避ける。AI の要約・判定には「AIによる分類。正確な内容は議会だよりの原文をご確認ください」と明記する。

## 出典

- 市議会だより一覧: https://www.city.minamisoma.lg.jp/portal/admin/shigikai/3/index.html （号ごとのページに PDF がある）
- 会議録検索システム: https://ssp.kaigiroku.net/tenant/minamisoma/pg/index.html
- 一般質問件名表（議事係）: https://www.city.minamisoma.lg.jp/portal/sections/70/7010/70102/index.html （件名と質問者の突き合わせと、議会だよりに載っていない件名・「その他の質問」の質問の要約に使う）

## ページ構成

URL: `/apps/questions/`（`src/pages/apps/questions.astro`）。タイトル（仮）「一般質問 みんなの論点」。

1. **ヒーロー**: 「ミニアプリ · 試作版」バッジ、見出し、リード、収録範囲（例: 「令和○年○月定例会〜令和8年6月定例会」）とデータ出典の一行。
2. **数字で見る** (`#numbers`)
   - 数字タイル3つ: 総質問件数、質問した議員数（質問が1件以上ある議員だけを数える）、収録した定例会数。
   - 議員×分野のクロス表。セルは件数。件数が多いほど背景色を濃くする（0件を除く8段階。文字と背景のコントラスト比4.5:1を満たす混ぜ方だけを使う。表の上に「少ない〜多い」の凡例を付ける。色は `global.css` の既存トークンから段階をつくる）。行合計（議員ごと）と列合計（分野ごと）、総計を表示する。
   - 行には任期中の議員全員を載せ、一般質問をしていない議員も0件の行として残す（名前のリンクは付けず、議長の印・※は付ける）。行の並びは現在の議席番号の大きい順（22→1）で固定する（失職した議員は当時の議席の位置）。件数順には並べない（順位付けに見えるのを避けるため）。議員の絞り込みセレクトには、質問のある議員だけを並べる。
   - セルを押すと、下の質問一覧をその議員×分野で絞り込み、一覧へスクロールする。行見出しなら議員だけ、列見出しなら分野だけで絞り込む。
   - スマートフォンではクロス表を横スクロールにし、議員名の列を固定する。
   - 議長を務めた議員は、行見出しの名前の右に小さな「議長」の印を付ける（`roles` から生成）。`note` のある議員には「※」を付ける。名前のリンクは今までどおり。議員の絞り込みセレクトでも、議長を務めた議員に「（議長経験）」、`note` のある議員に「※」を添える。
   - 表の直下に小さな注記を置く（データから生成）。1行目は「議長は議事を進める立場のため、議長を務めている間は一般質問を行っていません。」、続けて議長ごとに「<氏名>：<開始の定例会>〜<終了の定例会> 議長」、`note` のある議員ごとに「※ <氏名>：<note>」。議長の低い件数を質問の少なさと読み違えないための説明で、議員の評価とは結びつけない。
3. **主要トピック** (`#topics`、AI分析)
   - 分野ごとに、繰り返し取り上げられた論点を2〜4項目の短文でまとめる。各項目に、該当する質問の件数と代表的な質問へのリンク（一覧内のアンカー）を付ける。
   - その分野の定例会ごとの件数を小さな縦棒で添える（全分野で同じ目盛り）。
4. **答弁の方向性** (`#answers`、AI分析)
   - 5段階の件数を、全体1本と分野別の積み上げ横棒で示す。
   - 5段階の意味を凡例で説明する（下記「方向性の区分」）。
   - 全体の棒の凡例にだけ、方向性を判定していない件数（「答弁の要約なし」）を灰色の見本で添える。棒の一部には含めない。
5. **質問一覧** (`#list`)
   - 絞り込み: 議員、分野、定例会、方向性（それぞれセレクト。「すべて」あり）。フォームは `hidden` で出力し、スクリプトが動いたときだけ表示する（JavaScript が動かない環境では、使えないフォームを見せない）。複数の条件は AND で組み合わせる。該当件数を表示する。「条件をクリア」ボタンを置く。
   - 1件ごとのカード: 定例会名、議員名、分野バッジ、件名、質問の要約、答弁の要約、方向性バッジと判定理由の一文、市議会だより該当号へのリンク（掲載ページ付き。議会だよりに載っていない質問には付けない）、会議録検索へのリンク。
   - 並び順は定例会の新しい順、同じ定例会の中は議会だよりの掲載順。
6. **データと注意点** (`#method`): 出典、収録範囲、分類・要約・判定の方法、AI による判定の限界、議長と一般質問の説明（議長を務めた間は質問しない。件数は任期全体なので、質問できた期間の長さで差が出る）、誤りを見つけたときの連絡方法（既存のお問い合わせへ）。

## 分野の区分

一般的な行政分野で固定する。1件の質問は主分野を1つだけ持つ（集計は主分野で行う）。

| id | 表示名 |
|---|---|
| `childcare` | 子育て・教育 |
| `welfare` | 福祉・医療・健康 |
| `industry` | 産業・雇用・農林水産 |
| `recovery` | 震災復興・原子力災害 |
| `disaster` | 防災・消防・安全 |
| `town` | まちづくり・交通・公共施設 |
| `environment` | 環境・エネルギー |
| `community` | 地域・市民活動・文化・スポーツ |
| `admin` | 行財政・市役所運営 |
| `other` | その他 |

書き起こしの途中で、どこにも当てはまらない質問が目立つ場合は、区分を見直してから全体を分類し直す。

## 方向性の区分

答弁の要約から、市の結論がどれに近いかを1つ選ぶ。1件の質問に複数の小項目がある場合は、件名の中心となる小項目の答弁で判定する。

| id | 表示名 | 目安 |
|---|---|---|
| `doing` | 実施・実施予定 | 「実施する」「○年度から行う」「すでに行っている」 |
| `positive` | 前向きに検討 | 「前向きに検討する」「実施に向けて検討する」 |
| `study` | 研究・状況を見て判断 | 「研究する」「国の動向を注視する」「今後判断する」 |
| `status` | 現状説明のみ | 事実や現状の説明で、方向を示していない |
| `no` | 実施しない | 「考えていない」「困難」「予定はない」 |

判定理由は、要約中の根拠になる言い回しを踏まえた一文で書く。

## データ

### `src/data/questions.json`

```json
{
  "note": "市議会だよりに載った一般質問の要約をもとに書き起こした。市議会だよりに載っていない件名と「その他の質問」（件名のみ掲載）は、市議会の一般質問件名表（件名・要旨）から質問の側だけをまとめた。分野・方向性はAIによる分類。",
  "sessions": [
    {
      "id": "r8-06",
      "name": "令和8年6月定例会",
      "year": 2026, "month": 6,
      "issue": { "vol": 82, "date": "2026-08-01", "url": "https://www.city.minamisoma.lg.jp/portal/admin/shigikai/3/31753.html", "pdf": "https://…/xxx.pdf" }
    }
  ],
  "members": [
    { "id": "m01", "name": "氏名", "kana": "しめい" },
    { "id": "m02", "name": "氏名", "kana": "しめい", "roles": [{ "label": "議長", "from": "r4-12", "to": "r6-09" }], "note": "注記（任意）" }
  ],
  "questions": [
    {
      "id": "r8-06-01",
      "session": "r8-06",
      "member": "m01",
      "category": "childcare",
      "title": "件名（議会だよりの見出しどおり）",
      "question": "質問の要約（1〜3文）",
      "answer": "答弁の要約（1〜3文）",
      "direction": "study",
      "reason": "「国の動向を注視する」との答弁のため",
      "page": 5
    }
  ]
}
```

- `sessions` は定例会単位。1つの号が1つの定例会を扱う前提。例外があれば `issue` を定例会ごとに持たせているので、そのまま対応できる。
- `members` の `seat` は現在の議席番号（市議会の議員名簿、2026-08-27 更新）。表の並び順に使い、議員間で一意の正の整数。失職した議員は当時の議席番号（名簿の旧版で確認）。`kana` は議席番号が同じときの並べ替えに使う。質問が1件もない議員も載せる（任期中の議員全員）。
- `members` の `roles`（任意）は役職と期間（`from`〜`to` は定例会 id、両端を含む）。`label` が「議長」の期間は一般質問を行わないため、その期間の定例会に質問があればテストで失敗させる。`note`（任意）は表の下に出す注記（失職など）。根拠は議会だより・議員名簿。
- 1件の単位は、議事係の一般質問件名表の1件名（2026-09-30 にユーザーが決定）。`title` は件名表の件名どおり。`questions` の並びは件名表の順。
- 議会だよりで「その他の質問」として件名だけが載っている件名も1件として数える。答弁が載っていないため `direction` は `null`。
- `question` は議会だよりの記事があれば記事から、なければ件名表の要旨（なければ件名）から要約する。`answer`・`direction` は議会だよりの記事だけから書く。
- `page` は、その件名の記事または「その他の質問」の載っている PDF 上のページ番号で、リンクには `#page=<n>` を付ける。議会だよりに載っていない件名は `page` を省く。
- `question` と `answer` は要約で、原文の引用はしない（原文へはリンクでたどる）。

### `src/data/questions-analysis.json`

```json
{
  "generatedAt": "2026-10-xx",
  "topics": [
    {
      "category": "childcare",
      "points": [
        { "text": "論点の要約（1文）", "questionIds": ["r8-06-01", "r7-12-04"] }
      ]
    }
  ]
}
```

- `questionIds` の件数を「○件」として表示し、先頭の1件を代表としてリンクする。
- 先頭には、答弁の要約がある（`direction` が `null` でない）質問のうち、件名が論点を具体的かつ中立に表しているものを置く（質問者の主張が強い件名や「市長の政治姿勢について」のような総称の件名は、ほかに適当なものがあれば避ける）。論点の中に答弁のある質問が1件もなければ、件名がいちばん具体的なものを置く。2件目以降は定例会の新しい順。
- 方向性の集計は `questions.json` からページ側で計算する。分析 JSON には持たせない。

### `src/data/questions-meta.json` と `src/data/questions-types.ts`

分野・方向性の id と表示名の対応表、方向性を判定していない質問の表示（`noDirection`: 絞り込み用の `id`、表示名 `label`、カードの注記 `titleOnly`「市議会だよりでは件名のみ掲載」と `notInDayori`「市議会だよりに掲載なし」）、出典 URL は `questions-meta.json` に置く（テストからも読むため JSON にする）。`questions-types.ts` は上記の型を定義し、対応表を `CATEGORIES`・`DIRECTIONS`・`NO_DIRECTION`・`SOURCES` として型付きで再公開する。ページとコンポーネントはここから表示名と順番を取る（ハードコードしない）。

集計（クロス表、件数、並び替え）は `src/lib/questions-stats.mjs` の純粋な関数にまとめ、テストで確かめる。

## コンポーネント

- `src/components/CrossTable.astro`: 議員×分野のクロス表。行・列・セル件数を受け取り、濃淡と合計を描く。セル、行見出し、列見出しに `data-member` と `data-category` を付ける。
- `src/components/QuestionCard.astro`: 質問1件のカード。
- `src/components/DirectionBar.astro`: 方向性の積み上げ横棒（CSS の幅指定で描く）。
- `src/components/SessionBars.astro`: 分野ごとの、定例会別件数の小さな縦棒。
- 数字タイルは既存ミニアプリの表示に同じものがあれば流用し、なければページ内に置く。

## 絞り込みの動作

- 既存の `.filter-chips`（一次元のチップ）は条件を組み合わせられないため、`src/scripts/questions.js` を新しく作り、このページだけで読み込む。
- 各カードに `data-member`、`data-category`、`data-session`、`data-direction` を付ける。4つのセレクトの値で AND 判定して `hidden` を切り替え、該当件数を更新する。
- クロス表のセル・見出しを押すと、該当するセレクトを設定し（それ以外は「すべて」に戻す）、絞り込みを実行して `#list` へスクロールする。
- 絞り込みの状態は URL のハッシュに入れない（試作版では不要）。
- JavaScript が動かない環境では、絞り込みフォームは隠れたままで、全件が表示されたままになる。

## リンクの追加

- `src/data/tools.ts` に `questions` を追加し、「まちを知る」ページのカードに並べる。`art` は既存の種類から選ぶ（`paper` か `bars`）。
- README の「ファイル」と「試作段階の項目」に追記する。

## 作業手順（データづくり）

1. 対象の各号のページから PDF の URL を集め、`sessions` を作る。
2. PDF の文字を取り出し（`pdftotext` など）、一般質問のページから、議員・件名・質問の要約・答弁の要約・掲載ページを抜き出す。
3. 議事係の一般質問件名表と突き合わせ、件名と議員の抜けや取り違えを確かめる（入手できる範囲で）。
4. 分野と方向性を判定し、判定理由を書く。
5. 全件がそろってから、分野ごとのトピック分析を書く。
6. 抜き取りで10件ほど原文と見比べ、要約と判定を人（森山）が確かめる。

## エラー処理・欠損

- PDF の文字が取り出せない号（画像のみなど）は、画像から読み取る。読み取れない場合は `sessions` に `note` を付けて「未収録」と表示し、件数に含めない。
- 答弁の要約が議会だよりに載っていない質問（主に「その他の質問」）は `answer` を空にし、`direction` を `status` にせず `null` とする。方向性の集計からは除き、「答弁の要約なし」として件数を示す。
- 議会だよりに載っていない件名（`page` なし）は、カードに議会だよりへのリンクを付けず、会議録検索へのリンクだけを置く。方向性の欄には `noDirection.notInDayori`（「市議会だよりに掲載なし」）を注記する。議会だよりに件名だけ載っている「その他の質問」（`page` あり、`direction` が `null`）は `noDirection.titleOnly`（「市議会だよりでは件名のみ掲載」）を注記する。

## 範囲外

- 現任期より前の定例会。
- 会議録全文を使った分析、再質問・再答弁の細かな追跡。
- 議員ごとの評価、ランキング、得点。
- ページ上でその場で AI に質問する機能。
- 一般質問以外（代表質問、委員会、議案の賛否）。
