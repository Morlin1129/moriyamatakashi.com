# トップページの入口ページ化 設計書

作成日: 2026-09-24

## 目的

サイト全体は情報量が多く、読むのにそれなりの読解力が要る（本人の感覚で「偏差値60」）。トップページだけは、読解力に自信がない人でも読める入口ページにする（「偏差値45」でも読める）。下層ページの深さは変えない。

- 主な読者: 子育て世代・現役世代
- 読み終わる目安: スマホで2〜3分
- 言葉の基準: 中学生が読める語彙。一文は20字前後、一行一意。抽象名詞より動詞。
- 役割分担: トップ = 「誰が・何を・どうやって」を伝える入口。下層 = 根拠と詳細。トップから1クリックで届く。

## トップページの構成

現在の8セクション（ヒーロー／考え方／取り組み／進め方／資料と数字／プロフィール／ノート／問い合わせ）を、次の5セクションに再構成する。

### 1. ヒーロー（誰？を3秒で）

- 見出し: 「困りごとを、放っておかない。」
- 3行:
  1. 森山貴士（もりやま たかし）
  2. 大阪出身。2014年から南相馬・小高で暮らす、一児の父
  3. 子育てや仕事の「不便」を、市役所と一緒に直していきます。
- ボタン: 「くわしいプロフィール →」（/profile/）
- 写真は現在のヒーロー写真を継続。手書き風の添え書きはここには置かない。

### 2. こんな声を、聞いてきました。

3つの声を引用の形で並べる。断定ではなく「聞いてきた声」として書く。

- 「意見交換会で声を上げても、届いている気がしない」
- 「地域に不満はない。でも休みの日は、つい市外に遊びに行ってしまう」
- 「新しい会社の誘致は熱心だけど、ここで根を張ってやる人への応援が少ない」

締めの一文: 「こうした声を、放っておきたくない。ひとつずつ、形にしていきます。」

### 3. だから、これをやります。

5つの取り組みを「アイコン＋一文」のリストで並べる。写真・バッジ・長いタイトルは使わない。各行は下層の取り組みページへのリンク。

アイコンは5つの単色（サイトの緑）インラインSVG線画（子ども／買い物かご／建物と人／市役所／建物とお金）。`src/components/PolicyIcon.astro` に `name` プロパティで切り替える形でまとめる。YAML には `icon` フィールド（`children` / `odaka` / `economy` / `city-hall` / `future`）を追加してアイコン名を持たせる。

並び順（現役世代向けに変更）と一文:

| 順 | 取り組み（YAML） | 一文（`plain`） |
|---|---|---|
| 1 | children | 子どもが放課後に行ける場所と、外で遊べる機会をふやす |
| 2 | odaka | 小高の買い物・病院・移動を、今より楽にする |
| 3 | economy | 南相馬の会社が人を増やせるよう、後押しする |
| 4 | city-hall | 市役所の人が働きやすくなれば、サービスも良くなる |
| 5 | future | 古くなった建物とお金の話を、先送りせずに一緒に考える |

末尾に小さなリンク「数字や資料で見る →」（/resources/）。

### 4. どうやって進めるの？

3ステップを見出し＋一文で示す。

1. 聞いて、調べる: 困りごとを直接聞き、数字や資料でも確かめる。
2. 一緒に考える: 関わる人と早い段階から、やり方と費用をくらべる。
3. 小さく試して、結果を伝える: できるところから始め、良かった点も課題も伝えて次に活かす。

末尾に「くわしい考え方 →」（/vision/）。

### 5. 話を聞かせてください。

問い合わせボタン1つ（既存の `data-open="contact"`）。手書き風の添え書きはこのセクションだけに残す。

### 外すもの

- 「考え方」セクション（ヒーローと4に吸収）
- 「資料と数字」セクション（3の末尾リンクに縮小）
- 「まちを考えるノート」セクション（削除）
- 「プロフィール」セクション（ヒーローに吸収）
- 手書き風の添え書きは5以外すべて削除
- 写真はヒーロー写真と、3と4の間の風景写真1枚だけ残す

## 下層ページへの変更

「私の考え方」ページ（`src/pages/vision.astro`）の「大切にする、5つの進め方」を3つに組み替える。

- 見出し: 「大切にする、3つの進め方」
- 現在の1「現場で困りごとを聞く」と2「事実を確かめる」→「聞いて、調べる」に統合
- 現在の3「実現方法を一緒に考える」→「一緒に考える」
- 現在の4「できるところから試す」と5「結果を伝え、改善する」→「小さく試して、結果を伝える」に統合
- 各ステップの本文は、統合元の説明文を要約して1段落にまとめる。前後の段落（導入文・締めの文）の「5つ」表現も直す。

他の下層ページは変更しない。

## コードの変更点

- `src/content.config.ts`: `policies` スキーマに `plain: z.string()` と `icon: z.string()` を追加。
- `src/components/PolicyIcon.astro`: 新規。`name` に応じたインラインSVGを出す。
- `src/content/policies/*.yaml`: 各ファイルに `plain` と `icon` を追加。`order` はトップの並び順に合わせて付け直す（children=1, odaka=2, economy=3, city-hall=4, future=5）。`title`・`titleLines`・`lead` は変えない。
- `src/pages/index.astro`: 上記5セクションで書き直す。
- `src/pages/vision.astro`: 5ステップ→3ステップ。
- `src/styles/global.css`: トップ専用で使わなくなるスタイル（`.vision*`, `.resources*`, `.resource-*`, `.notes*`, `.note*`, `.profile*`, `.policy-grid`, `.policy*`, `.landscape` の一部, 5列の `.process-inner`, `.step-arrow` など）を削除し、新セクション（声の引用リスト、アイコン付き取り組みリスト、3ステップ）のスタイルを追加。既存の `--section-pad` で上下余白を揃える。下層ページで使われているクラス（`.step-list`, `.policy-card`, `.crop` など）は残す。
- ヘッダー・フッターのナビはトップ内アンカーを持たないため変更なし。
- `order` を変えると取り組み一覧ページ・前後ページャの順も変わる。これは意図した変更とする。

## 確認方法

- `astro build` が通ること（Node は nodebrew の v22.20.0 を使う）。
- PC幅（1280px）とスマホ幅（375px）でトップを表示し、5セクションが順に読めること、リンク先が正しいこと、コンソールにエラーがないこと。
- `/vision/` で3ステップが表示され、「5つ」の表現が残っていないこと。
- `/policies/` と各取り組みページで並び順と前後リンクが新しい `order` に沿っていること。
- 文言の微調整はページ上で見ながら行う。
